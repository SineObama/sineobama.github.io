## 废案说明

两个目录会有分别提交管理的需求，也更清晰分明，不需要合并。

## 概览

### 管理原则

- 使用文件系统 + 纯文本的 Markdown 格式文件，开放式的存储方式，享受全平台同步、检索和查看的便利。
- 使用自己喜欢的 Markdown 编辑器写笔记文章，不用被限制在专用笔记软件之中。
- 使用博客框架系统将（部分）文章输出成网页格式，方便公开发布到其它平台。

### 使用需求

- 核心聚焦文本笔记内容，集中在一个文件夹。如此可以方便自动同步和备份；根据同步工具的不同，体积最好小一些，图片资源不一定在此范围内。（暂没有图床的需求与使用经验）
- 博客框架一般要求文章内容在项目文件之内，设定一个或多个文件夹昨晚原始文件存放位置。
- 【核心】笔记文件（或其他文件）之间有链接关系，个人选择使用 Markdown 原生的相对路径引用，并希望发布后也能正常（使用相对路径）完成链接展示或跳转。

### 使用的工具/框架

- Obsidian 基于文件系统的 Markdown 笔记软件
- 坚果云 基于文件系统的文件自动同步
- Git 基于文件系统的版本管理（全自定义排除文件）
- Hexo 博客框架
- Gitee Git 远程仓库，用于发布公开的静态博客

### 核心技术预览

- 得益于 Hexo 基础框架及其高度自定义的功能：[插件系统](https://hexo.io/zh-cn/docs/plugins) 之 [过滤器（Filter）](https://hexo.io/zh-cn/api/filter#server-middleware) 对 [路由](https://hexo.io/zh-cn/api/router) 的入门级定制使用，博客页面路径可以实现“所见即所得”。

## 组织结构

### 目录结构

划定一个文件夹来存放所有内容，根目录是一个 Hexo 网站项目，主要文件有：

- \_config.yml
- package.json
- source/     *Hexo 资源目录，存放用户个人文件资源的地方*
	- \_posts/       *Hexo 发布文章的固定存放位置，我们也把它作为自动同步目录*
		- pub/          *正式的公开发布内容（根目录）*
		- notes/        *私有笔记（根目录）*
	- att/            *私有附件图片*
	- .git/           *个人文件的版本管理；冗余存储发布内容*
	- .obsidian/  *Obsidian 软件的配置与插件*
		- .git/         *配置与插件的版本管理（非必须，个人强迫症存档需要）*
- .git/          *Hexo 项目与正式发布内容的版本管理*

### 目录结构技术基础

Hexo 默认会包括 `source/` 下的文件和文件夹，但贴心的自动排除了 `.` 开头的文件和目录，支持配置 [包括或不包括目录和文件](https://hexo.io/zh-cn/docs/configuration#包括或不包括目录和文件) 这使得我们可以将个人文件存放于此，并且划分。

由于坚果云不支持排除文件，总体的目录层级最少有：

- Hexo 项目目录
	- 个人文件目录
		- 坚果云同步目录
			- 公开发布内容目录
		- .git 目录

#### 遗留问题与技术风险

- 我的文章和附件（图片）使用相对路径引用，但是 Hexo 项目中相隔了一层 `_posts` 文件夹导致路径不正确，想到有种方法是将附件也放在这个文件夹里，但试验发现需要在 `include` 配置里添加，否则它似乎只会识别文章。但 Hexo 这样设计可能也有其他理由，我们这样搞可能有风险。
- 目录合并后，本地文件会很多，本地 Hexo 构建时变慢，试验发现把排除的文件设置在 `ignore` 选项里比在 `include` 中能有效提高性能。
